\chapter{Perception and Observation Space Design}
\label{ch:perception}

\section{Bird's-Eye View Observation}

The RL agent receives observations from two complementary sources: a vector of state variables and a bird's-eye view (BEV) image rendered from the simulation environment. This observation design is motivated by the prior ME~780 work, which used only vector state observations (cross-track error, heading error, velocity), and extends it to include visual perception of lane boundaries and obstacles.

The BEV image is generated by a configurable camera anchored to the tractor's rear axle, rendering a top-down $84 \times 84$ grayscale image of the vehicle and its surroundings from the Pygame simulation. The anchor point and zoom level are configurable in the simulation settings. The image encodes lane markings, obstacle positions, and the vehicle geometry relative to the lane, providing the agent with spatial context that the vector observation alone cannot capture.

\section{CNN Encoder}

A Convolutional Neural Network (CNN) serves as the front-end of the RL agent, processing the BEV image to extract spatial features relevant to lane tracking and obstacle avoidance. The CNN enables the agent to perceive the environment directly from rendered images, without requiring a pre-defined symbolic representation of every object.

The CNN architecture is implemented as a custom feature extractor within the Stable Baselines3 framework, following an ImageEncoder design. The extracted image features are concatenated with the vector state observations before being passed to the TD3 actor and critic networks. This combined observation allows the policy to leverage both precise state information and rich spatial context.

The CNN is trained end-to-end with the TD3 agent, allowing the feature extractor to learn which visual features are most relevant for path maintenance and collision avoidance.

\section{Autoencoder Latent Space}

To improve RL training efficiency, an autoencoder can be used to compress high-dimensional BEV image observations into a compact latent representation. The encoder $E(\cdot)$ maps the image observation $s$ to a latent vector $z$, and the decoder $D(\cdot)$ reconstructs the original image:

\begin{equation}
    z = E(s)
    \label{eq:encoder}
\end{equation}
\begin{equation}
    \hat{s} = D(z)
    \label{eq:decoder}
\end{equation}

The autoencoder is pre-trained on images collected from simulation rollouts, allowing the encoder to learn compact representations of the road geometry and obstacle configurations. The RL agent then operates on $z$ rather than the raw image, reducing the number of parameters the policy network must learn and potentially improving convergence.

\section{Observation Space Summary}

The full observation space is a dictionary with two components:

\begin{tabular}{p{3cm} p{4.5cm} p{5.5cm}}
\toprule
Component & Description & Role \\
\midrule
\texttt{vector} & State variables: steering angle, hitch angle, cross-track error, heading error & Provides precise numerical state information to the policy \\
\texttt{image}  & $84 \times 84$ grayscale BEV image rendered from Pygame simulation & Encodes spatial context: lane markings, obstacle positions, vehicle geometry \\
\bottomrule
\end{tabular}
\end{table}

Collision detection is performed using Pygame sprite mask overlap, enabling pixel-precise detection of contact between the vehicle body and obstacles or lane boundaries. Episode termination is triggered on collision, jackknife ($|\gamma| > 90^\circ$), or path completion.
