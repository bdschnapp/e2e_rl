\chapter{Simulation Environment}
\label{ch:simulation}

\section{Custom Pygame/Gymnasium Environment}

The training and evaluation environment is a custom 2D simulation built on the Farama Foundation Gymnasium library, consistent with the approach taken in the ME~780 prior work. Gymnasium provides a standardised API for implementing environments that integrate directly with reinforcement learning algorithm libraries, including Stable Baselines3.

The simulation is implemented using Pygame for rendering and physics integration. At each timestep, the discrete-time tractor-trailer state-space equations are re-evaluated using the previous state and control inputs, updating the vehicle position, heading, hitch angle, and associated error signals. Pygame renders the scene as a 2D top-down view, from which the BEV image observation is captured.

The simulation environment includes:

\begin{enumerate}
    \item \textbf{Vehicle Model}: A combined dynamic tractor (bicycle model with Pacejka tire dynamics) and kinematic trailer with hitch constraints, using Tesla Model S parameters as in the ME~780 and ECE~682 prior work.
    \item \textbf{Lane Generation}: Randomly generated lane paths using cubic spline interpolation, producing varying curvature paths for training and evaluation.
    \item \textbf{Obstacle Placement}: Randomly placed static obstacles within the lane, used in the obstacle avoidance task.
    \item \textbf{Collision Detection}: Pygame sprite mask-based collision detection, providing pixel-precise contact sensing between the vehicle body and obstacles or lane boundaries.
    \item \textbf{BEV Camera}: A configurable bird's-eye view camera anchored to the tractor's rear axle, rendering an $84 \times 84$ grayscale image of the vehicle and its surroundings.
\end{enumerate}

\section{Environment Tasks}

Two distinct Gymnasium environments are implemented, corresponding to the two primary research tasks:

\subsection{Line Following}

The lane-following environment extends the base tractor-trailer environment to present a lane-tracking task. A reference lane is generated at the start of each episode using cubic spline interpolation through randomly placed waypoints. The reward function encourages the agent to keep both the tractor and trailer within the lane boundaries while maintaining forward progress.

The observation at each timestep includes:
\begin{itemize}
    \item \texttt{vector}: steering angle $\delta$, hitch articulation angle $\gamma$, cross-track error $e_y$, heading error $e_\psi$, and their time derivatives;
    \item \texttt{image}: an $84 \times 84$ grayscale BEV image rendered from the tractor rear axle anchor point.
\end{itemize}

\subsection{Obstacle Avoidance}

The obstacle avoidance environment adds static obstacles within the lane. The agent must navigate the tractor-trailer through the lane while avoiding obstacles, which requires both path-following behaviour and collision avoidance. Episode termination occurs on collision, jackknife ($|\gamma| > 90^\circ$), or successful path completion.

\section{Action Space}

The agent controls the vehicle through a continuous two-dimensional action space:
\begin{equation}
    \mathbf{a} = [\dot{\delta},\, v] \in [-15^\circ/\text{s},\, 15^\circ/\text{s}] \times [0,\, 2\,\text{m/s}]
    \label{eq:action_space}
\end{equation}

where $\dot{\delta}$ is the steering rate (rate of change of steering angle) and $v$ is the commanded speed. This action parameterisation is consistent with the observation from the ECE~682 work that the steering angle cannot be set instantaneously on a physical vehicle; controlling the rate of change is more physically realistic.

\subsection{Obstacle Avoidance}

The obstacle avoidance task tests the agent's ability to navigate through a lane containing static obstacles. Success is measured by collision rate and the agent's ability to complete the lane while maintaining hitch stability.

\subsection{Comparison with Prior Work}

Results are compared against:
\begin{itemize}
    \item the DDPG model from ME~780 (cross-track error 0.505\,m on single-vehicle path following);
    \item a PID baseline from ME~780 (cross-track error 0.784\,m);
    \item an LQR-based baseline from ECE~682;
    \item an MPC controller implemented using OSQP.
\end{itemize}
